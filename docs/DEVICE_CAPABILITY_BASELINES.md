# Sensor, HomeBase, and doorbell baselines

The Mega gateway records small core capability decisions for these three device families. Each family has a definition-only core file, and the camera, sensor, HomeBase, and doorbell rows pass through one shared evaluator. The authenticated `GET /api/device-capabilities` endpoint shows recognition, gateway support, per-row evidence, and whether an existing path can be offered. Current values remain in the normalized camera and sensor APIs rather than this shape-only endpoint.

HomeBase 3, T8030/type 18, has an existing managed-station path. Its core catalogue lists inventory availability, connection, guard and effective modes, alarm state, volume and tone controls, firmware, and eMMC/HDD storage. A ready route indicates the station read or command path is available, not that a particular value has been refreshed. HomeBase 2 T8010/type 0 is admitted separately as a read-only station with inventory identity, firmware, availability, child-camera route readiness, and a conservative local mode read. Its mode sensors appear only after that read succeeds. It does not inherit T8030 writes, alarm controls, or storage commands. T9000/type 27 is recognized as a station-class peer but remains outside these controls. Its command protocol is not verified.

Doorbells keep their existing camera media, motion/person events, and battery reads. The doorbell-specific core row is the transient press event already routed from known push code 3103. A doorbell's camera route can be ready without proving that press notifications or video work on that physical model. The MiniBase Chime is a media peer, not a doorbell entity.

Known standalone sensor types stay out of camera admission. The gateway admits only the capabilities each row proves: parameter 1550 for contact state, 1101 for battery percentage, 1551 for last-seen time, and recognized PIR types for motion pushes. Contact push code 3 carries settled open or closed state. PIR push code 14 creates a transient motion state. Inventory-backed values refresh every 60 seconds. Home Assistant creates the matching entities under a separate sensor device. Real installed sensor hardware still needs to confirm this end-to-end path.

The gateway adds optional features only after building and testing its own decode or command path. Grouped diagnostics show the family admission decision, whether a Home Assistant adapter exists, reported core fields, unimplemented reads, route readiness, and currently offerable gateway paths. They omit device names, serials, raw parameter values, and push payloads. Recognition alone never admits an unverified station or a sensor capability without matching evidence.
